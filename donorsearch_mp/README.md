# Аналитика продаж DonorSearch Shop на маркетплейсах (Яндекс Маркет и Ozon)

Комплексный аналитический проект по управлению ассортиментом мерчандайза на маркетплейсах. 

Проект реализован в виде модульного ETL-пайплайна с валидацией качества данных, расчетом сквозной юнит-экономики, ABC-анализом, оценкой воронки конверсий и формированием приоритизированного реестра управленческих действий по каталогу SKU.

---

## Ключевые результаты и бизнес-инсайты

1. **Ядро коммерческой эффективности — Яндекс Маркет:**
   - На общем сопоставимом периоде (июль 2025 — июнь 2026) Маркет показал выручку **1 120 529 руб.** и чистую прибыль **474 057 руб.** при маржинальности **42.3%** и среднем чеке **600 руб.**
   - Ozon за тот же период сгенерировал **572 754 руб.** выручки и **217 623 руб.** прибыли при марже **38.0%** и среднем чеке **516 руб.**
   - **Управленческое решение:** инвестиции в масштабирование продаж и маркетинговый бюджет приоритетно направлять в Яндекс Маркет.

2. **Особенности ценообразования и субсидирования скидок Ozon:**
   - Скидки на Ozon субсидируются баллами площадки (средняя глубина скидки — 5.7%, или 35–40 руб./ед.).
   - Для финансового контроля необходимо отслеживать фактические цены покупателя ($P_{buyer}$) и продавца ($P_{seller}$), так как номинальная «текущая цена» в отчетах не отражает реальную экономику транзакции.

3. **Кейс термостаканов (риск запоздалой ликвидации):**
   - Анализ выявил эпизоды распродажи артикулов `термо_*` по цене 46 руб. (Маркет) и 146 руб. (Ozon) при базовой себестоимости 780 руб.
   - Продажи значительно ниже себестоимости привели к прямой отрицательной валовой прибыли еще до вычета услуг логистики.
   - **Управленческое решение:** контроль оборачиваемости и затоваривания на ранних этапах, отказ от поздних глубоких дисконтов в пользу оперативного управления складскими лимитами.

4. **Воронка конверсий Яндекс Маркета:**
   - Основное узкое горлышко воронки находится на этапе **«показ → корзина»** (конверсия **0.5%** при 1.72 млн показов). 
   - Конверсия из корзины в оформленный заказ составляет **26.5%**, процент выкупа доставленных заказов — **73.6%** (1 712 выкупленных единиц).
   - Приоритет оптимизации — кликабельность главного фото (CTR) и рейтинг карточек, а не накачка нецелевого трафика.

5. **Реестр решений по каталогу SKU (122 позиции):**
   - Проведена сегментация матрицы «Продажи × Маржа» с расчетом грейдов ABC по выручке и прибыли.
   - Сопоставлены сигналы складской ликвидности (выявлено 166 позиций Маркета и 16 позиций Ozon со статусом избытка или отсутствия продаж).
   - Сформирован реестр рекомендаций с ранжированием по приоритету: `Перепрайсить` (1) → `Ликвидировать остаток` (2) → `Увеличить видимость` (3) → `Масштабировать` (4) → `Кандидат на вывод` (5) → `Не поддерживать закупку` (6).

## Архитектура проекта

Проект спроектирован по модульному принципу Medallion (Raw → Interim → Processed → Output / Analytics):

```text
donorsearch_mp/
│
├── data/
│   ├── raw/                 # Исходные файлы выгрузок (исключены из репозитория)
│   │   ├── Маркет/
│   │   └── OZON/
│   └── external/            # master_sebestoimost.csv (справочник себестоимости)
│
├── interim/                 # Слой 1 (Extract): промежуточные типизированные Parquet-кэши
│   ├── ym_raw.parquet
│   ├── ozon_raw.parquet
│   ├── funnel_raw.parquet
│   └── stock_raw.parquet
│
├── processed/               # Слой 2 (Transform): аналитические витрины
│   ├── mart_sku_month.parquet        # Единая витрина: SKU × месяц × площадка
│   ├── mart_platform_month.parquet   # Сводная помесячная динамика площадок
│   └── mart_sku_summary.parquet      # Агрегированные метрики с ABC-грейдами
│
├── output/                  # Слой 3 (Metrics & Actions): итоговые бизнес-артефакты
│   └── sku_recommendations.csv       # Приоритизированная таблица решений по SKU
│
├── notebooks/
│   └── 03_analysis.ipynb    # Аналитический отчет, дашборды, визуализации и выводы
│
├── src/                     # Исходный код конвейера обработки данных
│   ├── __init__.py
│   ├── config.py            # Динамические пути, бизнес-пороги, патчи себестоимости
│   ├── market.py            # Парсинг и очистка отчетов Яндекс Маркета
│   ├── ozon.py              # Парсинг юнит-экономики и начислений Ozon
│   ├── extract.py           # Оркестрация сбора данных (Extract)
│   ├── transform.py         # Расчет юнит-экономики и построение витрин (Transform)
│   └── metrics.py           # Матрица SKU, ABC-анализ и реестр решений (Metrics)
│
├── .gitignore               # Исключение конфиденциальных данных и кэшей
├── README.md                # Документация проекта
└── requirements.txt         # Зависимости окружения
```

## Инженерные особенности и контроль качества данных

* **Устойчивая дедупликация:** выгрузки Маркета очищаются от побайтных дубликатов файлов через MD5-хэширование. Повторяющиеся заказы дедуплицируются с сохранением самой актуальной версии по дате формирования отчета.
* **Независимый финансовый Sanity-Check:** 
  - Расчетные показатели прибыли Ozon сверены с итоговым отчетом площадки (расхождение < 1 руб. на строку из-за копеечных округлений, статус PASS).
  - Фактические расходы на услуги доставки Маркета верифицированы с контрольным интервалом (77 715 руб. при ориентире 76 000 – 80 000 руб., статус PASS).
* **Отказ от жестких путей:** пути определяются динамически через `pathlib.Path`, обеспечивая переносимость кода между ОС (Windows, macOS, Linux).
* **Семантический поиск колонок:** исключено хрупкое обращение по индексам столбцов (`iloc`) в отчетах Ozon с многострочными подсказками — поиск ведется по ключевым фразам через функцию `find_col`.
* **Строгая типизация Parquet:** устранена проблема смешанных типов данных в строках Excel, гарантирующая мгновенное считывание витрин в памяти.

##  Инструкция по запуску и просмотру

> **⚠️ Примечание о данных:** Проект выполнен на реальных коммерческих данных. Первичные выгрузки маркетплейсов (`data/raw/`) и промежуточные parquet-витрины (`data/interim/`, `data/processed/`) скрыты в `.gitignore`. 
> 
> **Для быстрого просмотра графиков и выводов** запускать код не требуется — все результаты уже сохранены внутри ноутбука **[`notebooks/03_analysis.ipynb`](notebooks/03_analysis.ipynb)** (открывается прямо в GitHub) и в итоговом файле рекомендаций **[`output/sku_recommendations.csv`](output/sku_recommendations.csv)**.

### Полный воспроизводимый запуск (при наличии исходных выгрузок)

**1. Клонирование репозитория и установка зависимостей**
```bash
git clone https://github.com/gleb-zakalyakin/data-analyst-portfolio.git
cd data-analyst-portfolio/donorsearch_mp
pip install -r requirements.txt
```

### 2. Запуск пайплайна данных (ETL)
После размещения исходных отчетов в папке `data/raw/OZON/ и data/raw/Маркет/` запуск выполняется последовательно:
```bash
# 1. Извлечение сырых выгрузок и сохранение в промежуточный слой (parquet)
python src/extract.py

# 2. Очистка, расчет юнит-экономики и сборка аналитических витрин
python src/transform.py

# 3. Расчет матрицы SKU, ABC/XYZ-анализа и генерация рекомендаций
python src/metrics.py
```

### 3. Работа с аналитическим отчетом
После сборки витрин в data/processed/ вы можете перезапустить ноутбук локально:
```bash
jupyter notebook notebooks/03_analysis.ipynb
```
Либо откройте файл `notebooks/03_analysis.ipynb` напрямую в VS Code и нажмите **Run All**.
